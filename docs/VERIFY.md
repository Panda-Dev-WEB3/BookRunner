# VERIFY register

Every external fact the protocol depends on but does not control. Mainnet (Robinhood Chain, 4663)
deployment is blocked until every row is **Confirmed** and the action column is done (RUNBOOK
"Mainnet" preconditions).

Status values:

- **Confirmed**: checked against the cited primary source (protocol docs or the protocol's own
  source code). Still re-check addresses byte-for-byte on-chain (`cast code <addr>` is non-empty, and
  the ABI matches) right before deployment.
- **Divergent**: confirmed, and it differs from what the devnet code or the spec assumes. Action needed.
- **Unconfirmed**: no primary source found, or only third-party sources.

Research date: 2026-10-02 (A-orderly cluster); §3 and §6 updated 2026-10-10 (mainnet prep package 3:
USDG settlement, Uniswap routes, BKRN TWAP). Sources were read through a summarising web fetch, so
every address below must be re-verified on-chain before use. The owner is the cluster that must act.

## OrderlyAdapter deployment parameters

- Implementation constructor: `OrderlyAdapter(bytes32 defaultBrokerHash, bytes32 defaultTokenHash)`.
  Deploy / upgrade scripts hash `DEPLOY_ORDERLY_BROKER_ID` and `DEPLOY_ORDERLY_TOKEN` (passed through by
  `scripts/forge.sh`). Devnet: `(keccak256("bookrunner"), keccak256("USDC"))`. Mainnet (RHC):
  `(keccak256(<ORDERLY_BROKER_ID>), keccak256("USDG") = 0x50c06f78...5b02ea)`; `config.usdc()` must be the token
  `getAllowedToken(tokenHash)` returns, with 6 decimals. The hashes are copied into each proxy at `initialize`.
  New defaults for future books mean a new implementation, registered through the timelock-gated factory
  implementation setter. Existing books keep their hashes across upgrades.
- Accounts (v3): every new book gets an `OrderlyIFAccount` at `initialize` (owner of the IF account; MM is the
  adapter's own account). The timelock must call `adapter.setDelegateSigner(<ops-venue EOA>)` (registers the EOA for
  the adapter AND its IF account on the Vault); ops-venue then confirms both with `POST /v1/delegate_signer`.
- Upgrade path for live (testnet) adapters: `UpgradeOrderlyAdapters.s.sol` (timelock) deploys the v3
  implementation, registers it for future books and upgrades every Orderly proxy. Storage is append-only
  (`ifAccount` packs into the slot of `lastSweptPeriod`); upgraded proxies keep their devnet account ids and
  balances. `MIGRATE_ORDERLY_ACCOUNTS=true` additionally migrates adapters with nothing venue-side
  (`migrateToOrderlyAccounts()`); restart ops-venue and mock-orderly afterwards. Mainnet is a fresh deployment.
- Native deposit fee: keep each adapter funded (`fundNative`) or set `OPS_NATIVE_TOPUP_MAX_WEI` (O5).
- Config: `venueMinIfUsd[Orderly] = 25,001e6` (O10).
- Mainnet blockers still open for the adapter: O10 (Orderly accepting a contract account as the symbol's IF
  account), O11 (per-symbol fee revenue with more than one Orderly book), broker id (O7).
